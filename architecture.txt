# Quiz System Architecture

## Overview
This document outlines the architecture for a universal quiz system that can handle multiple deck formats, question types, and language directions. The system is designed to be extensible, allowing for future enhancements like LLM-powered question generation.

The quizzing system and loading system have been redesigned to be fully universal, working with any dataset regardless of language or content type. The vocabulary system now supports any language pair, removing hardcoded assumptions about specific languages like Arabic-French.

Key improvements:
- Universal dataset support: Any language pair can be used, not limited to predefined ones.
- Flexible wrong answer generation: Wrong answers for multiple-choice questions are populated randomly from entries in the selected categories.
- Quiz generation: Users can select categories to cover, choose question types for automatic generation, and also create "hardcoded" questions where they manually define correct and incorrect answers without needing to import from a deck.

## Core Components

### 1. Universal JSON Schema

All quiz decks follow a standardized JSON format:

```json
{
  "metadata": {
    "title": "Deck Title",
    "version": 1,
    "deck_type": "vocabulary|qa|grammar|etc",
    "language_pair": ["source_lang", "target_lang"],
    "description": "Description of the deck",
    "supported_question_types": ["mcq", "write_word", "translate"],
    "default_direction": "source_to_target"
  },
  "categories": {
    "category_key": {
      "title": "Category Title",
      "difficulty": "beginner|intermediate|advanced",
      "properties": {}
    }
  },
  "entries": [
    {
      "id": "unique_entry_id",
      "category": "category_key",
      "data": {
        "source_text": "Question text in source language",
        "target_text": "Answer text in target language",
        "additional_fields": "as needed"
      },
      "tags": ["tag1", "tag2"]
    }
  ]
}
```

Note: The `language_pair` field supports any languages, not limited to specific pairs. Source and target languages can be any valid language codes (e.g., "en", "fr", "ar", "es", etc.).

### 2. Data Loading System

#### UniversalImporter
- Handles any deck in the universal JSON format
- Validates structure and converts to internal `ParsedDeck` format
- Replaces format-specific importers

#### ParsedDeck Structure
```go
type ParsedDeck struct {
    DeckKey    string
    Title      string
    Version    int
    Categories map[string]string
    Questions  []ParsedQuestion
    Metadata   DeckMetadata
}

type ParsedQuestion struct {
    ID             string
    CategoryKey    string
    QuestionText   string
    CorrectAnswer  string
    AdditionalData map[string]interface{}
}
```

### 3. Question Generation System

#### Question Types
- `mcq`: Multiple choice questions
- `write_word`: Free text input
- `translate`: Translation exercises
- `custom`: User-defined questions with manually specified correct and incorrect answers
- Future: `conjugate`, `tense_identification`, `grammar_correction`

#### Directions
- Dynamic based on language pair: e.g., `source_to_target`, `target_to_source`
- Extensible to any language pair defined in the deck metadata

#### QuestionGenerator Interface
```go
type QuestionGenerator interface {
    CanGenerate(questionType QuestionType, direction Direction, deckMetadata DeckMetadata) bool
    Generate(entry DeckEntry, questionType QuestionType, direction Direction) (*GeneratedQuestion, error)
}

type GeneratedQuestion struct {
    QuestionText  string
    CorrectAnswer string
    Options       []string // For MCQ
    QuestionType  QuestionType
    Direction     Direction
}
```

#### VocabularyQuestionGenerator
- Handles vocabulary-specific question generation
- Supports MCQ, write_word, translate, and custom types
- For MCQ, generates wrong answers by randomly selecting from entries in the selected categories
- For custom questions, uses user-provided answers without deck dependency

```go
type QuizConfig struct {
```

#### CustomQuestion
```go
type CustomQuestion struct {
```

#### QuizGenerator
- Creates quizzes based on configuration
- Randomly selects question types and directions for auto-generated questions
- Includes user-defined custom questions as specified
- Uses appropriate generators for each entry, drawing wrong answers from selected categories

### 5. Data Source System

#### DataSource Interface
```go
type DataSource interface {
    GetName() string
    GetType() string
    GetRandomAnswers(ctx context.Context, excludeQuestionID int64, count int, filters map[string]interface{}) ([]string, error)
    CanHandle(filename string, rawData []byte) bool
    Parse(rawData []byte) (*ParsedDeck, error)
}
```

The `GetRandomAnswers` method now filters by selected categories to provide contextually relevant wrong answers for multiple-choice questions.

#### DataSourceRegistry
- Manages all available data sources
- Auto-discovers appropriate importer for files

## Future Enhancements

### LLM-Powered Features

#### 1. Verb Conjugation Questions
- **Question Type**: `conjugate`
- **Description**: Show infinitive form, ask user to conjugate in specific tense/person
- **LLM Integration**: Use LLM to generate conjugation questions and validate answers
- **Example**:
  ```json
  {
    "question_type": "conjugate",
    "verb": "aller",
    "tense": "présent",
    "person": "1sg",
    "correct_answer": "vais"
  }
  ```

#### 2. Tense Identification
- **Question Type**: `tense_identification`
- **Description**: Show conjugated verb, ask user to identify the tense
- **LLM Integration**: Generate varied examples and distractors
- **Example**:
  ```json
  {
    "question_type": "tense_identification",
    "verb_form": "allait",
    "options": ["présent", "imparfait", "futur"],
    "correct_answer": "imparfait"
  }
  ```

#### 3. Grammar Correction
- **Question Type**: `grammar_correction`
- **Description**: Show sentence with errors, ask user to correct
- **LLM Integration**: Generate realistic errors and validate corrections

#### 4. Contextual Translation
- **Question Type**: `contextual_translate`
- **Description**: Show word in sentence context, ask for translation
- **LLM Integration**: Generate natural sentence contexts

### LLM Integration Architecture

#### LLMQuestionGenerator
```go
type LLMQuestionGenerator struct {
    llmClient LLMClient
    baseGenerators []QuestionGenerator
}

func (l *LLMQuestionGenerator) CanGenerate(questionType QuestionType, direction Direction, metadata DeckMetadata) bool {
    // Check if LLM can handle this type
    return l.isLLMQuestionType(questionType)
}

func (l *LLMQuestionGenerator) Generate(entry DeckEntry, questionType QuestionType, direction Direction) (*GeneratedQuestion, error) {
    prompt := l.buildPrompt(entry, questionType, direction)
    response := l.llmClient.Generate(prompt)
    return l.parseResponse(response, questionType)
}
```

#### Adaptable LLM Models
The system supports multiple LLM models with different capabilities and costs:

```go
type LLMClient interface {
    Generate(prompt string, options LLMOptions) (string, error)
}

type LLMOptions struct {
    Model       string  // "gpt-4", "gpt-3.5-turbo", "claude-3", "local-model", etc.
    Temperature float32 // Creativity level
    MaxTokens   int     // Response length limit
    Quality     string  // "trash", "basic", "good", "premium"
}

// Model Selection Strategy
func selectModelForTask(questionType QuestionType, complexity string) string {
    switch questionType {
    case "conjugate":
        if complexity == "advanced" {
            return "gpt-4" // High accuracy needed for complex conjugations
        }
        return "gpt-3.5-turbo" // Sufficient for basic conjugations
    case "tense_identification":
        return "claude-3-haiku" // Cost-effective for classification tasks
    case "grammar_correction":
        return "gpt-4" // Needs strong language understanding
    default:
        return "local-model" // Use cheapest available for simple tasks
    }
}
```

**Model Selection Criteria:**
- **Trash/Basic Models**: Simple conjugation, basic MCQ generation, straightforward translations
- **Good Models**: Complex grammar, contextual examples, nuanced explanations  
- **Premium Models**: Advanced linguistic analysis, creative content generation, detailed feedback

#### LLM Validation
- Use LLM for answer validation in complex question types
- Fallback to exact matching for simple types
- Provide detailed feedback and explanations
